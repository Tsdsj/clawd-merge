# T10 挑战服务端与正式模式

状态：2026-10-03 本地实现与验证完成。沿用已确认 T09 界面与规则，接通正式能力；未提交、推送或部署。完整接口见 [后端说明](../../leaderboard/README.md)，证据见 [T10 记录](../verification/m2-t10.md)。

- 独立 `/api/challenges/*` 路由和 D1 表，不复用经典局凭证或经典榜单。上海日期、题目版本、100 投与次日 00:10 截止由服务器确定。
- `GET today` 返回权威题目、serverNow、当前身份当日剩余次数；未登录仍可取题练习。
- `POST session` 输入 challengeId、rulesVersion、requestId；相同请求重放原凭证。原子写入凭证与次数，最多 3 次，响应丢失不多扣。客户端先持久化请求标识，未知结果不能换新标识重试。
- `GET session/check` 只核验本人原凭证，不领新机会；恢复按原题和原截止。身份不符／网络失败保持原记录，明确转练习后不恢复正式资格。
- `POST score` 只接受正式凭证及匹配题目／版本，校验 1—100 投、分数、最高等级、道具次数、结束原因与结算时长。首次接受须在截止前；已接受回执可在截止后重放。凭证消费、成绩、个人题目最佳和回执同事务提交。
- `GET leaderboard` 按题目查榜和本人排名，正分按分数降序、首次达到时间升序，毫秒相同以 player ID 稳定排序。练习、经典和不同题目不能混榜。
- 游客绑定已有 LINUX DO 身份时合并已用次数（相加，不退回）、历史结果及每题最佳；客户端要求先处理未完成正式局、未知开局和待提交记录。游客换身份的滥用仍受注册限流约束，不声称强防作弊。
- 客户端继续使用独立挑战存档。正式结束先保存完成记录，再进入挑战专用 Outbox；身份、题目、版本和对局标识一起保留。复用有限重试与跨页上传锁，不把 token 写入结果记录。

顺序：服务端协议与事务测试 → 正式开局／恢复／上传接线 → 今日榜与异常界面 → 本地真实浏览器及 workerd/D1 并发验证。

开局重放同时返回当前 status，已结束／过期记录不可重新开玩。恢复客户端还核对 attempt、startedAt 与 submitUntil 不变。正式同页手动暂停不重复发核验请求；刷新、身份变化及后台返回需复核。
