# T08 可复现规则与随机源

范围：基于已确认的开发规划，实现随机与规则基础，不增加每日挑战入口、账号次数或榜单，不部署。经典模式界面与计分行为沿用 M1。

## 接口与边界

- `src/random.js`：每个 Game 独立持有 `GameplayRandom`。算法标识 `mulberry32-1`，32 位整数状态，`next()` 返回 `[0, 1)`；支持导出／恢复状态。默认使用 Web Crypto 生成初始 seed，旧环境只在创建时回退读取一次 `Math.random()`。不将这个 PRNG 用于 token、防作弊或安全标识。
- `src/rules.js`：集中现有经典规则常量，`classic-1` 不变；冻结权重与规则对象。`Game` 继续导出 `RULES`，兼容既有调用。
- `src/drop-sequence.js`：经典模式调用 `chooseClassicLevel(random, game)`，保留成长解锁；未来挑战调用 `createChallengeSequence({challengeId, rulesVersion, count})`，一次生成只读序列。
- `new Game(canvas, events, {seed})` 可显式传入测试 seed；生产调用方式不变。绘制、粒子、眨眼仍使用独立的视觉随机调用，不再推进玩法流。`physics.js` 不含随机调用，因此不修改求解器。

T08 没有把挑战结果接入经典 Game／存档／排行榜：挑战对局接线与其专用存档属于 T09，服务端身份与榜单隔离属于 T10。这样当前线上经典入口不会出现“挑战局被当作经典局上传”的半成品路径。

## daily-1 序列定义

- ID 为 1—128 个 ASCII 字母、数字、下划线、冒号或短横线，版本必须明确为 `daily-1`；未知版本拒绝，不静默换题。
- 以 `JSON.stringify([rulesVersion, challengeId])` 的 UTF-8 字节经 FNV-1a 生成 32 位 seed，再使用 `mulberry32-1`。count 不参与种子，所以请求更长序列不会改变已有前缀。
- 第 1 只固定为等级 1；后续普通掉落固定使用等级 1—5 的权重 `[22,22,22,18,16]`。与经典模式不同，挑战不根据玩家最高等级扩大可选池。
- 彩虹概率保持 3.5%，不连续出现；最早位于从 0 开始的索引 16，即第 17 次投放。这与经典模式“15 次投放后生成下下只”的预览语义一致，不把第 15 次投放误当成彩虹立即可用。
- 参数 count 接受 1—1000，1000 只是内存分配防护，不是每日对局上限。100 投、每日正式次数与结算窗口仍需 T09 明确。
- 一旦某版本用于题目，不可直接改算法、编码、权重、彩虹资格或抽样次序。变更须新增版本和固定向量，并保留旧版本解析能力。当前只支持 `daily-1`。

32 位种子可能碰撞，序列也可能偶然相同。题目身份必须使用 challengeId 与 rulesVersion，不能用 seed 当唯一标识。题目可复现不等于跨设备刚体逐帧一致，也不等于可服务端重算成绩或防作弊。

## 存档兼容

经典快照新增可选的 `gameplayRandom: {algorithm, state}`；外层 schemaVersion 仍为 1、rulesVersion 仍为 `classic-1`，因为游戏规则和既有字段含义不变。

- 新快照恢复 RNG 状态，保留当前／下一只之外的后续随机抽样位置。
- 旧快照没有该字段时继续接受，保留其中棋盘、当前与下一只；后续用新建游戏的随机流。旧版本没有持久化未来随机状态，不能承诺精确还原。
- 字段存在却损坏、算法未知或状态越界则拒绝，不降级为随机重开；校验与世界重建成功后才替换 Game 状态。
- 续玩后若合成进度不同，经典成长池仍可能变化；这里只保证相同规则输入时抽样连续。

## 验证

新增单测覆盖 PRNG 固定向量／零 seed／恢复／非法状态、日题固定向量与前缀、全局随机隔离、经典概率边界、特效与眨眼隔离、新旧快照兼容及原子拒绝。`test/fixtures/daily-1.json` 中两道 100 项向量由独立 Python 整数参考生成，Node 和浏览器使用同一组固定预期值防止静默漂移。

本地浏览器验证入口为 `/test/randomness.html`：检查两道题各 100 项，真实 Canvas 绘制下比较普通与额外特效／4 倍绘制的 100 次掉落，再比较恢复后的 30 次掉落。该页不写存档或上传成绩，仅隔离页内音效，不修改声音偏好。

实施验证（2026-10-02）：`npm test` 共 100 项通过，新增 9 项；Chromium 154 浏览器页面显示“全部通过：版本向量、绘制隔离、续玩序列”。正式游戏入口也完成一次投放的自动保存、刷新、继续恢复及测试局清理。未推送或部署，未测试手机硬件；相同整数序列不代表物理逐帧结果相同。
