## 1. 结论与范围

建议沿用原生 ES Module + Canvas、Cloudflare Worker + D1，在同一个 `player.id` 上增加密码登录能力，保留游客与 Linux.do 登录。密码账号和 Linux.do 是可以同时存在的登录方式，不建立两套成绩、挑战和存档体系。

本轮需求拆成一个账号交付包与一组有证据的修复：

1. 用户名密码注册、登录、游客升级、修改密码和最小恢复能力；用户名允许重复，完整登录账号带编号。
2. 服务端统一名称审核，覆盖注册、改名及外部身份的公开展示；本地词库可维护、可回滚、可处理误拦。
3. 一个账号可同时使用密码和 Linux.do；显式区分登录、绑定与游客成绩合并。
4. 新界面沿用现有画风，先原型、设计确认，再接入正式功能。
5. 修复本轮已复现的四项问题，并处理账号请求超时、凭据保存失败等相关体验缺口。

不扩展新玩法、周榜、云端棋盘同步、聊天、邮箱短信服务或通用后台。跨设备登录保证同一服务器玩家和成绩，不意味着本机棋盘、图鉴、舒适设置自动同步。

用户已确认：暂无指定敏感词库或审核标准，先采用“可维护的本地词库＋服务端校验＋误拦处理”。授权执行 A00 后，第 10 节产品规则按推荐值收敛到接口契约；这不表示用户逐项单独确认，也不包括购买套餐或新增运行服务的授权。

## 3. 账号产品规则

### 3.1 同名与登录标识

推荐把“登录账号”和“展示昵称”明确区分：注册输入 `小螃蟹`，服务器分配 `小螃蟹#4821`，完整字符串作为唯一登录账号；另一人可得到 `小螃蟹#9073`。不能只按裸用户名查找后逐个试密码，也不通过公开接口列出同名账号。

- 注册成功突出完整账号，提供复制按钮，密码管理器的 username 保存完整值；密码允许粘贴。
- 登录账号首版固定不变。展示昵称可修改，修改时提示不会改变登录账号；账号面板同时清楚展示二者，避免用户忘记编号。
- 注册名与昵称沿用现有 2—12 字和字符规则，编号由服务器生成，输入不能自带 `#` 冒充分配结果。
- 规范化统一使用 NFKC 与英文大小写归一；四位编号包括前导零。密码不做 trim、大小写转换或 Unicode 归一化。
- 游客升级优先保留现有名称、编号与玩家 ID；若登录账号空间存在历史冲突，先告知新的完整账号，再完成升级，不静默覆盖。
- 唯一性由数据库约束保证，并发冲突重试；同名前缀编号耗尽时给出明确错误并允许换名。不要承诺无限同名，也不要仅凭八次随机碰撞断定一万个编号已满。

这比裸用户名更适合同名需求，也比额外要求邮箱/手机号更符合小游戏的轻量定位。若决定“改名同时修改登录账号”，需在 A00 改定规则并补充旧名失效、并发改名与密码管理器提示，不能实施到一半混用两种语义。

### 3.2 四种身份与转换

| 当前身份 | 可用操作 | 必须保持的结果 |
| --- | --- | --- |
| 匿名本地玩家 | 继续玩、注册密码账号、创建游客、Linux.do 登录 | 当前本地局不追溯上榜；登录本身不消耗挑战机会 |
| 游客 | 原地设置密码升级、绑定 Linux.do、改名、退出 | 升级密码不换 ID、不清记录、不重置挑战次数 |
| 仅密码账号 | 密码登录、改密、绑定 Linux.do | 绑定后两种方式返回同一 ID，保留完整登录账号 |
| 仅 Linux.do 账号 | OAuth 登录、设置本地用户名密码 | 新增凭据挂到原玩家，历史成绩和头像保留 |
| 密码＋Linux.do | 任一方式登录、改密、管理绑定 | 两个入口进入同一玩家、最佳成绩与挑战配额 |

### 3.3 绑定、冲突与成绩合并

- **绑定未占用 Linux.do 身份**：挂到当前玩家，保留本地登录账号；头像和 L 标记可继续来自 Linux.do。
- **Linux.do 已绑定当前玩家**：幂等成功，不重复迁移历史、不改变机会。
- **Linux.do 已属于另一正式账号**：返回绑定冲突，引导登录已有账号；首版不自动合并两个正式账号，不能仅凭同名、相同密码或一个 OAuth 回调转移资产。
- **游客进入已有 Linux.do 账号**：保留现有合并能力，先处理未完成正式局、未知开局及待上传记录；采用修复后的事务合并，最佳成绩取正确胜者，同分取更早达成时间，局数和已用挑战次数只累计一次。
- **游客用密码登录一个已有账号**：视为切换身份，提示先处理游客待办和存档；首版不悄悄合并两个玩家。若想保留游客历史，引导先在该游客上设置密码。
- 首版不提供解绑/换绑 Linux.do 或删除唯一登录方式；后续如需要，再定义二次验证、冷却和恢复规则。
- 登录与绑定使用显式 action。OAuth state 绑定 action、来源玩家、发起会话与一次性随机值；绑定前核验近期凭据，回调再次确认来源及会话有效性。登出后旧绑定请求不得生效。
- 关闭弹窗、切换身份、刷新及请求晚返回不能改变另一账号；需要统一身份版本和请求失效机制。

### 3.4 密码、会话与恢复

- 按2026-10-04用户确认，密码最少 6 字符、最多 128 字符，按 Unicode code point 计数，允许中文、空格和长口令；不强制拼凑大小写与符号。提供显示/隐藏密码和确认密码。
- 密码只通过 HTTPS 请求体传输，不进入 URL、日志、localStorage、分析事件或错误回显。D1 只存盐、派生值、算法与参数版本。
- 登录失败统一提示“账号或密码不正确”，不存在账号也执行相当成本的校验路径；先做 IP 与账号维度的原子限流，再执行昂贵计算，不做永久账号锁死。
- 修改密码验证旧密码；Linux.do-only 首次设密与通过 Linux.do 恢复须近期重新授权。改密/恢复撤销旧会话，给当前设备签发新 token。
- 推荐首版提供一次性高熵恢复码：仅创建/轮换时展示，服务端存哈希；使用后轮换并撤销旧会话。未绑定 Linux.do 且恢复码丢失时明确无法自助找回，不用昵称、排名或截图证明所有权。
- 新正式账号 token 推荐 30 天绝对有效期，无操作不无限续期；老游客 token 不突然失效。迁移前明确老 Linux.do 会话的兼容期，不能让存量游客失去唯一凭据。
- 注册成功但本机保存失败：本页可用，明确提示未记住登录状态并展示完整账号；不重复创建账号。前端超时不能证明注册未成功，注册需有受限生命周期的幂等设计，重试不能生成第二个账号或向未证明持有者泄露 token。

## 4. 技术路线与名称审核

### 4.1 路线比较

| 方案 | 收益 | 代价与判断 |
| --- | --- | --- |
| **现有 Worker/D1 增加凭据，推荐** | 游戏结构和 ID 不变；不增加外部账号厂商；词库可离线维护 | 需自行负责密码安全、恢复、限流和兼容迁移；先验证密码算法能在目标运行时安全执行 |
| 接入托管认证服务 | 减少部分认证实现工作 | 增加厂商、价格/配额、数据和跨域集成约束；同名与原玩家合并仍需自己处理，首版不推荐 |
| 独立自托管认证后端 | 密码算法与算力限制更可控 | 增加服务器运维、补丁、监控与网络链路；仅在现有 Workers 无法满足安全/预算时评估 |

密码哈希是 A00 前置验证，不把“零依赖”当作降低安全强度的理由：优先评估 Argon2id 的成熟实现；若原生 Web Crypto PBKDF2 能满足安全参数与预算，也可减少依赖。OWASP 当前给出 Argon2id 基线，以及 PBKDF2-HMAC-SHA256 600,000 次的建议参数；具体选型需结合部署实测。[密码存储参考](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)

Workers 文档列出 PBKDF2 能力，但不代表当前部署支持任意迭代次数；workerd 的上限调整 PR 本轮查阅时仍为 Open，并指出开源运行时与继承默认限制的部署存在差异。**Node/本地 workerd 成功不能替代目标 Workers 测试**，不得把 100,000 次悄悄当成最终安全配置。[Web Crypto](https://developers.cloudflare.com/workers/runtime-apis/web-crypto/)、[上限讨论](https://github.com/cloudflare/workerd/pull/7550)

先测算法支持、单次 CPU、内存、登录延迟和并发拒绝行为；记录目标套餐。官方当前文档的 Free CPU 限额为每请求 10 ms，不能承诺新增密码认证仍零成本。若需要付费套餐或新增服务，先给出实测与费用方案再作决定；不自动购买，不用客户端预哈希或自写密码算法绕过限制。[Workers 限额](https://developers.cloudflare.com/workers/platform/limits/)

### 4.2 最小数据与接口改造

继续以 `players.id` 为玩家主键，首版复用现有 `linuxdo_id` 唯一约束，不另外维护一张重复的 Linux.do 身份表。

- 新增 `password_credentials`：`player_id` 唯一、`login_handle_key` 唯一、原始登录账号、密码算法/盐/派生值/参数、凭据版本与更新时间。保留历史账号 handle，不与展示昵称共用可变 `name_key`。
- 新增恢复码记录；token 增加签发方式、认证时间、到期时间等必要字段。注册幂等记录只保存完成请求所需的最小信息，定义 TTL 与清理策略。
- players 必要时增加展示名来源和审核状态；现有 `token_hash` 是历史随机凭据哈希，**不能拿来充当密码哈希**。
- `/api/me` 返回私有 `authMethods`、`canSetPassword`、`canRename` 等能力；公共榜单只返回展示所需信息，不泄漏恢复状态或凭据元数据。
- `publicPlayer` 不再一看到 Linux.do 就强制隐藏本地编号。兼容保留 `linuxdo` 字段，但客户端不能再用它的反值判断游客。
- 新迁移从 `0005_*` 起，按实际拆分确定；不改 0001—0004 历史迁移。

建议接口，A00 固化契约后再实现：

| 入口 | 职责 |
| --- | --- |
| `POST /api/register` | 保留原游客注册兼容；同样执行名称审核 |
| `POST /api/auth/password/register` | 匿名注册或经过明确授权的游客原地升级，返回完整登录账号 |
| `POST /api/auth/password/login` | 完整账号＋密码登录，签发当前设备 token |
| `POST /api/account/password` | 设置/修改密码，区分首次设置与旧密码验证 |
| `POST /api/auth/password/recover` | 恢复码恢复；成功后码失效、旧 token 撤销 |
| `POST /api/account/recovery-code` | 近期认证后创建/轮换恢复码 |
| 现有 `/api/auth/linuxdo/start`、callback、exchange | 增加显式登录/绑定/近期验证意图，保持旧客户端安全兼容 |
| 现有 `/api/me`、`/api/rename`、`/api/logout` | 能力展示、统一改名审核、当前会话撤销 |

凭据与玩家升级写入必须原子化；绑定冲突由数据库唯一约束最终裁决。旧客户端发起 OAuth 时，服务端按玩家真实能力识别正式账号，不能让旧版 `!linuxdo` 逻辑触发正式账号合并。

### 4.3 名称审核与词库维护

已确认采用本地词库，不接按请求计费的审核 API。它是产品名称策略，不能宣称存在一份永久完整的“大陆敏感词官方清单”，也不能保证识别所有谐音、语义和新表达。

1. **来源**：以有明确来源与许可的公开数据作候选，筛选与用户名有关的类别，记录来源版本、许可证、更新时间和变更说明。可先评估 [houbb/sensitive-word-data](https://github.com/houbb/sensitive-word-data)；该项目提供独立词库，但本项目尚未采纳、下载或评估覆盖率。不引入 Java 运行时，也不把上游 Java 检测性能当作 Worker 性能证据。
2. **策略**：产品保留词、基础审核词库、项目增补词和精确例外分层。常用人名/地名等正常样本必须作为误拦测试，不照搬所有上游条目。
3. **规范化**：长度/字符规则与审核分开；NFKC、大小写、不可见控制字符、有限分隔符绕过均有测试。繁简变体采用明确的映射或词条；首版不进行泛化拼音/谐音全拦，以免扩大误伤。
4. **服务端权威**：游客注册、密码注册、改名、设置本地账号名共用模块。前端只做格式提示，不能通过直接调用接口绕过；词库加载/校验失败时拒绝新的命名操作，不影响已登录游玩与历史成绩查询。
5. **Linux.do 名称**：登录证明身份与名称展示审核分离。命中时允许正常登录，展示安全的中性别名和编号，提示设置合规昵称；原 Linux.do 身份仍按 provider ID 识别。排行榜、身份栏、结果和分享卡使用同一安全展示名。
6. **存量用户**：先只读扫描输出数量与匿名类别，人工核对误拦；上线时使用安全展示替代，不删除账号/成绩，不阻断原登录账号认证。以后登录时不要把历史账号名当成新的注册名再审核而造成锁号。
7. **维护**：词库与规则带版本，变更前跑允许/拒绝语料回归；误拦通过项目维护入口反馈，经核实修改精确例外，不让客户端白名单覆盖服务端。记录规则 ID 和版本，不记录密码或不必要的完整用户输入。更新失败可回滚到上一审核版本。

敏感词变更不修改存档中的 playerId、sessionId 或凭据。已有本地分享图片无法收回；新生成分享卡与当前界面需采用最新安全展示名，不能承诺清除互联网上的历史图片。

## 5. 界面与体验范围

### 5.1 视觉基线

不新增玻璃效果、品牌渐变、异形图标或一套独立设计系统；“像素风”不意味着把输入框正文改成难读的像素字体。

### 5.2 原型交付

在 `docs/prototypes/account/` 提供与业务隔离的可点击原型、关键高保真图和交互说明：

- 原“加入排行榜/选择身份”入口：密码登录/注册、Linux.do 与游客均可找到；仍可直接本地玩。
- 注册与成功：同名规则、密码可见切换、完整账号复制、恢复码与保存失败状态。
- 登录与恢复：忘记编号提示、账号或密码错误、限流倒计时、网络超时、Linux.do 恢复路径。
- 账号面板：游客升级、仅密码、仅 Linux.do、双登录方式四种状态；显示当前能力而非错误标成游客。
- 绑定确认与冲突：说明保留哪些资料；处理经典/每日待办，不覆盖原局。

验收覆盖 320px/390px 竖屏、桌面、844×390 横屏、软键盘挤压、长名字、加载/错误/成功/存储失败。真实验证输入焦点、Tab/Escape、Enter 提交、自动填充、不误触游戏快捷键和弹窗关闭后恢复原暂停状态。

原型先确认结构与流程，再对关键状态出图；图片不能代表可交互原型或手机实际验收。设计确认前不接业务功能。

### 5.3 与本次相关的体验改善

- 账号及榜单请求目前多处没有设置超时，统一明确等待、取消、重试与错误信息；写请求不能盲目自动重发。
- 注册成功后的凭据持久化失败必须可见；明确“本页可用”与“下次能自动登录”的区别。
- 同一账号增加登录方式不重置棋盘；切换到另一账号则保留旧局归属，并按现有规则提示本地继续或先处理。
- 经典与每日界面共用身份组件和能力判断；错误状态使用同样文案，不出现一边称正式账号、一边称游客。
- 保留动态偏好和 reduced-motion，不增加装饰性弹跳。手机后台、长局、真实 OAuth 属于待验场景，不预先宣称有新缺陷。

## 6. 本轮已复现的缺陷与修复计划

以下均为隔离环境证据，不代表生产已经发生数据损坏。复现未改动仓库测试或业务代码；实施时将场景转成正式回归。

| ID / 优先级 | 实际结果与代码依据 | 修复方向 | 验收结果 |
| --- | --- | --- | --- |
| **B01 / P1 并发限流失效** | `index.js:534` 的 rateLimit 先读后写。在空计数下对同 IP 同时发 12 次游客注册，限制为每小时 5 次，实际 12 次全部 201，计数最终仅 1 | 条件 UPSERT/原子计数与窗口重置；统一复用于注册、登录、改密/恢复等入口；拒绝时返回 Retry-After | 并发允许数不超过额度；临界窗口、不同 IP/账号、真实 D1 下结果正确；不能先跑昂贵哈希后限流 |
| **B02 / P1 合并令最佳成绩回退** | `index.js:295—342` 在事务前读取双方并判断 better。目标旧分 100、游客 200，合并 batch 前目标已变 300，合并后变回 200 | 在同一事务内基于当前值选择最佳元组；幂等认领来源玩家/合并操作；保护局数、经典回执和每日数据 | 较高分永不回退；同分取更早记录；并发重复回调只合并一次；失败不部分迁移 |
| **B03 / P2 排名不一致** | `index.js:473` 按列表序号赋名次，`rankOf:526` 只计更高分或更早时间。两个玩家均 100 分、best_at=1000：榜单为 1/2，两个 `/api/me` 都返回 1 | 与每日榜一致，用 score DESC、best_at ASC、id ASC 形成完整顺序；同步榜单、个人名次和新成绩回执计算 | 同分同毫秒时结果一致且稳定；已经持久化的历史回执保持提交时快照，不重写历史排名 |
| **B04 / P1 延迟改名覆盖新身份** | `src/leaderboard.js:124` 改名请求回来后 `save(player)` 使用此刻 token。A 发起改名，退出并登录 B，再返回 A 响应，最终是 A 的 playerId＋B 的 token | 请求捕获 playerId/token/身份版本；只允许匹配当前身份的响应提交；注册、登录、退出和跨页身份变化一并审计 | 延迟响应不能复活已退出账号或覆盖 B；同账号并发改名结果有顺序；服务器处理与 UI 取消区分清楚 |

复现步骤摘要，可据此建立正式测试：

1. B01：调用实际 `worker.fetch`，隔离 DB，无已有计数，`Promise.all` 发送 12 个相同 IP、不同合法名字的注册。
2. B02：mock OAuth 建立目标账号；创建游客；分别写入 100/200 的最佳分；在合并 batch 执行前注入目标更新到 300，再完成真实 callback，查询 `players.best_score`。
3. B03：隔离注册两人，设置同分同时间，比较榜单各行与两次 `/api/me`。不依赖两人列表的偶然先后。
4. B04：实际客户端模块发起待返回的 rename；forget A 并保存 B；返回 A 的改名结果；检查 playerId 与 token 归属。

B02 的额外并发场景已在A01补验；以上表格保留规划时的原始缺陷描述。当前修复与验证范围见 [A01记录](verification/a01-account-correctness.md)，不等于生产已经发布。

## 8. 验收矩阵

| 领域 | 必测场景与标准 |
| --- | --- |
| 同名 | 两个同名注册成功但账号不同；前导零；归一化一致；并发分配；冲突/耗尽不覆盖别人 |
| 密码 | 长口令与 Unicode；错误密码与不存在账号同类响应；算法/参数升级；未认证不能设密/改密；数据库/日志无明文 |
| 注册可靠性 | 双击、重试、响应丢失、刷新、本机禁写，不重复升级/创建，不把成功误显示为可再次注册 |
| 审核 | 所有新名称入口一致；直接 API 绕不过；变体/不可见字符；正常样本不过拦；外部及存量名称安全替代且不锁账号 |
| 绑定 | 四种身份的转换；重复 callback/state/code；回调期间退出/切号；已占用冲突；同时绑定；伪造目标玩家拒绝 |
| 账号恢复 | 旧密码验证；恢复码一次性且并发只能消费一次；Linux.do 近期授权；旧 token 撤销；恢复后旧成绩仍属同一玩家 |
| 经典 | 原榜、最佳分、并发合并、稳定排名、旧空 POST 开局、暂停/刷新/换号/补传；本地局不补发资格 |
| 每日 | 正式/练习隔离；绑定累计已用机会且不超过可用额度；未知开局恢复；跨日截止；旧回执不覆盖新结果 |
| UI | 既有样式对照、320px/横屏/软键盘；键盘/自动填充；错误可恢复；弹窗与背景状态互不误解除 |
| 兼容 | 旧游客和 L 站账号可继续用；旧存档可打开；旧前端对新后端仍安全；凭据到期不会偷换归属 |

自动化使用已有 `npm test`、`npm run test:http`、`npm run test:d1`；涉及认证事务需增加真实 workerd/D1 场景。密码成本另外验证目标部署限制，不能只依赖模拟 DB 或本地 runtime。

浏览器使用隔离测试账号/API，默认后台运行；真实第三方授权与手机系统行为由可用环境实际操作或用户验收。没有真实 OAuth 成功证据时标记待验，不能用 mock 测试替代。

## 9. 迁移、发布与回退

1. 发布前导出可恢复数据库备份，记录 migration 版本；在隔离副本跑完整旧数据迁移。检查孤儿关联、唯一冲突、玩家总量与两类最佳成绩一致性。
2. 先部署兼容后端与增量 schema，再发布前端；注册/新绑定能力有独立开关。名称审核开关不能导致开放注册时绕过审核。
3. 涉及新字段的客户端和旧字段客户端同时测试。旧 OAuth 启动路径遇到正式账号不能继续按游客合并。
4. 回退前端可关闭新入口，但后端要保留已注册用户的密码登录和安全约束。不能退回会清空编号/误合并的旧后端，也不删除新凭据表或恢复覆盖新数据的旧备份。
5. 若算法/成本或绑定验证未达标，先交付经过验收的 bug 修复；密码注册保持关闭，不用弱配置抢上线。
6. 发布后检查资源版本、登录/绑定失败码与超时、限流、D1 查询成本、两类成绩提交。优先复用现有只读运维工具；不默认新增第三方分析、定时任务或敏感日志。
