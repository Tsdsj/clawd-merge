# A05 · 双登录方式与游戏接线

日期：2026-10-04。状态：实现与工程验证完成；未部署、未执行生产迁移。沿用 A02 已确认原型、A00 契约和 A04 原生账号服务。

## 交付

- 密码账号先验证当前密码再绑定 Linux.do；绑定后两个方式进入同一玩家 ID，固定登录账号、本地昵称及历史保留。已归属其他正式账号时明确冲突，不泄露对方资料、不合并、不提供解绑。
- Linux.do 单方式账号通过新一轮 OAuth 设置本地密码；linked 可通过新 OAuth 恢复密码，正式账号可按能力轮换恢复码。证明限定玩家、token、版本与用途，五分钟且单次消费。仅 Linux.do 尚无完整本地账号时，界面提示恢复码不能代替 Linux.do 登录，应先设置密码登录。
- `0007_oauth_account_flows.sql` 增量迁移；0001—0006 未修改。新 OAuth 操作绑定随机 browser nonce 与 A04 操作证明，回调只暂存加密授权材料，兑换才原子绑定/合并和签发结果。一次性 code 两分钟、原操作十分钟；短期回执可重复读取，不能重新创建账号或重复迁移成绩/次数。
- 新增正式凭据时撤销源旧会话；游客合入已有 Linux.do 时清除源游客凭据、合并历史与已用机会，目标原会话保持。legacy 登录路径兼容，但正式密码账号不能被旧游客合并路径吞并。
- 取消授权、取消未完成意图、退出、改密、恢复、身份变化、过期和并发回调均有明确结果。取消不能假称已经提交的操作被撤销。提供方请求有超时，不记录外部错误 payload、密码、nonce 或 token。
- 前端使用本标签页 sessionStorage 保存 OAuth nonce/code/操作证明，失败时不导航；密码与 reauth grant 不持久化。跨页旧回跳不能覆盖新登录状态，丢失兑换响应可刷新后取回同一次结果。
- 会话过期保留本机玩家与对局，支持原账号重新登录；错误外部身份不会被采用。新身份不能接管另一玩家保留的正式局。
- 同玩家 OAuth 前保存经典棋盘、原凭证及手动暂停，包括零投放但已有凭证的局；返回后核验原局。每日模式返回原模式，保留正式凭证和机会；同玩家 token 轮换重新核验原资格，旧 token 的迟到资料响应不会覆盖新状态。未完成每日正式局或未安全保存的记录阻止切换身份。
- 运维报告加入过期 OAuth 密文清理及 nonce/context 脱敏，仍为只读预览、每批至多 500 行。未新增定时任务、线上配置或依赖服务。

## 真实浏览器证据

使用 `test/password-account-browser.mjs`、内存 SQLite、合成账号和 `test/oauth-provider-fixture.mjs` 的独立 loopback OAuth 服务。**不是实际 Linux.do 账号或生产数据**。所有浏览器后台运行，未抢占用户前台。

| 驱动脚本 | 已验证结果 |
| --- | --- |
| `test/oauth-account-flow.cjs` | 注册→绑定→linked→OAuth 恢复；经典棋盘、原局凭证和手动暂停保留，无额外经典开局 |
| `test/oauth-account-daily.cjs` | 每日正式局阻止退出；OAuth 轮换恢复码返回每日模式；改密后仍是同局、99 次剩余投放、2/3 次剩余正式机会 |
| `test/oauth-account-set-password.cjs` | Linux.do-only→新 OAuth 验证→设密→linked；零投放的原经典凭证也不替换；浏览器不保存 grant |
| `test/oauth-account-loss.cjs` | 服务端兑换完成后延迟 9.5 秒，页面超时；刷新取回原回执，无第二次外部授权或重复账号 |
| `test/oauth-account-conflict.cjs` | 绑定已属于另一个正式账号的外部身份，原密码账号不变，冲突可安全退出 |
| `test/oauth-account-relogin.cjs` | 仅撤销当前合成 token；旧局/身份保留；选错外部账号被拒绝，选择原账号后恢复原凭证 |
| `test/oauth-account-tabs.cjs` | 同一浏览器第二页更新登录 token；第一页面的旧 OAuth 回跳不会覆盖它，也不会完成绑定 |

账号和冲突截图已人工检查，沿用既有深色/橙色设计。截图、临时数据和浏览器日志不入库。A04 密码注册/改密/找回浏览器驱动另行回归。

启动普通 OAuth fixture：`CLAWD_FIXTURE_OAUTH=1 node test/password-account-browser.mjs`；丢包场景另加 `CLAWD_FIXTURE_DROP_EXCHANGE=1`。脚本验证 loopback 来源，避免误向真实环境写入。不同全流程使用新的 fixture 或按各脚本说明顺序运行。
