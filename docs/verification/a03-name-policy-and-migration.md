# A03 · 名称策略与账号数据基础

日期：2026-10-04。状态：实现与工程验证完成，未部署、未执行生产迁移。

依据：[A00 契约](../design/account-contract.md)、[账号开发计划](../account-system-plan.md)。已确认的 A02 原型保持不变。

## 交付

- `leaderboard/src/name-policy.js`：新命名、旧名公开展示、历史登录账号规范化相互独立。游客注册与改名已接共用审核；公共个人资料、经典与每日榜统一输出安全名称。
- `leaderboard/data/name-policy/`：固定来源、原许可证、NOTICE、摘要和标签统计。首版 69 个基础条目、4 个项目规则、6 个明确变体、1 个精确例外；并未直接启用 64,419 条上游主词库。见[维护说明](../../leaderboard/data/name-policy/README.md)。
- `0005_account_foundation.sql`：新增账号凭据、恢复码、二次验证证明、受保护操作回执与登录账号预留表；扩展玩家、token、OAuth state/code。0001—0004 未修改。
- 稳定别名由数据库单调计数器分配，唯一约束兜底；删除玩家不复用已提交的序号，事务失败可整体回滚。公开输出不改变原始姓名或登录账号。
- `leaderboard/ops/name-audit.mjs`：只读聚合扫描，支持迁移前数据库，不输出个人数据。未扫描生产库。
- Docker 构建清单包含本地数据目录；CI 增加生成包一致性检查。没有新增业务依赖或在线审核服务。

## 兼容与约束

- 旧 player ID、名字、token 哈希、经典/每日历史、局凭证和挑战次数保留。0001 与 0004 起点均已测试。
- 迁移时将已有 Linux.do token 到期元数据设为迁移时刻加 30 天，游客仍为无到期；不是按历史 created_at 立即过期。旧插入路径由兼容 trigger 填充元数据。
- **A03 只准备认证元数据，旧认证路径尚未执行新的 auth_version/到期检查。** A04 必须统一实现会话校验、签发、旧凭据撤销及 OAuth 版本绑定；不能把这些列的存在当作会话安全功能已上线。
- `password_credentials` 按玩家唯一，原始与规范化完整登录账号分别唯一；改公开昵称不会改变它。
- 登录账号预留与已生效凭据的插入/改键均互斥。A04 需在同一事务中消费预留再插入凭据；回滚会恢复预留。
- 恢复码按玩家唯一；二次验证的 token 和玩家由联合外键约束，删 token 同步撤销证明。完成态回执要求密文、nonce 与密钥版本字段，但真正的加密、签名、actor/purpose/TTL 校验仍在 A04。
- 词库不可用时拒绝新命名；已有账号仍能登录、开局、提交成绩。公共名称改用已有别名，不把外部名称审核当成身份验证失败。
- 新增密码注册、密码登录、改密和恢复接口仍返回 404，没有开启密码账号入口。

## A04 接续要求

1. 沿用 A02 已确认原型及本数据结构；scrypt 参数与凭据编码在认证实现中验证。
2. 登录账号分配优先复用当前编号；确实遍历空间或数据库证明耗尽后才返回 `name_crowded`，不能沿用游客的八次随机尝试作为密码账号分配策略。
3. 正式凭据出现前必须修正旧 OAuth 入口对“无 Linux.do 即游客”的判断，禁止正式密码账号被旧合并路径吞并。
4. 实现会话版本、到期、操作回执、二次验证、响应丢失重试、TTL 清理与密码负载门禁后才开放入口。本轮没有新增定时任务。
5. 客户端安全名称刷新、分享卡和本地缓存处理在后续接线验收；服务器安全输出不能清除旧截图或保证未刷新的旧客户端显示立即更新。
6. 发布阶段先备份、只读扫描并核对误拦，再在授权内执行生产迁移。恢复旧程序不等于可以直接删除新增表列；数据库回退需与备份及账号写入状态一起制定。
