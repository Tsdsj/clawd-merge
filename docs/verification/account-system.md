# A06 · 账号系统综合验收

日期：2026-10-04。工程检查与本轮修正完成；未部署、未执行生产迁移。真实 OAuth2 按用户确认记录，本轮依要求不重复发起真实授权。手机软键盘与实际密码管理器仍待人工确认，不能用桌面引擎或视口模拟替代。

依据：[账号计划](../account-system-plan.md)、[接口契约](../design/account-contract.md)、[A04](a04-password-accounts.md)、[A05](a05-linked-accounts.md)。既有有效证据按文件与行为是否变化复用，不把用户确认、自动化和生产验证混为一项。

## 本轮发现与修正

| 问题 | 修正与证据 |
| --- | --- |
| 改密仍可覆盖不支持的密码参数版本；KDF 期间仅改变版本时，旧登录结果可能通过复核 | 登录/改密统一拒绝未知版本；事务内比较 algorithm、params_version、盐、派生值及身份版本。新增两项回归先失败、修正后通过。当前只支持既定 scrypt v1，不宣称已实现未来算法的自动升级 |
| 删除本机操作记录失败却清空内存，下一次准备会被残留 ID 卡住 | 删除并确认成功后才清空；失败保留原意图并报告可重试错误。新意图先检查/持久化，再替换内存；新发现的另一页意图不被覆盖。单元回归及浏览器故障注入通过 |
| 恢复信息未保存时连续按 Escape 可跳过确认界面 | 第二次 Escape 返回恢复信息；主动放弃仍走明确按钮。三引擎均已验证 |
| WebKit 鼠标打开账号面板后，关闭会把焦点留在正文 | 账号入口显式聚焦，再记录返回位置；覆盖经典入口、结果入口和每日入口。WebKit 失败场景修正后通过 |

独立只读审查确认凭据版本修复；发现的本机存储 P2 已修正并复核关闭。完成态清理失败，以及错误密码自动取消后的清理失败，都保留原操作并提供重试入口。

| 每日局 | 三引擎验证练习不请求正式凭证；正式开局仅扣一次；未完成局阻止换号；刷新仍为原局、剩余99次投放与2/3次机会。未知开局、补传与跨日边界沿用对应自动化回归 |
| 兼容/持久化 | 迁移、旧客户端、旧存档、SQLite 重启与事务回滚继续通过测试；本轮没有改迁移文件。D1 兼容证据沿用 A05，CI 仍执行该回归；新密码服务为 Node 路线 |
| UI/无障碍 | 三引擎五种视口、短窗口、表单空格不投放、Tab/Shift+Tab 循环、Enter、Escape、回焦、密码字段 autocomplete 语义、存储故障可恢复；截图人工检查通过 |

| 目标服务器负载与发布 | A07 | 本轮不测试生产容量、不启用密码 overlay、不重启线上容器 |

人工验收只需覆盖以下具体动作：手机窄屏打开注册/改密，键盘弹出后查看输入框和提交按钮；通过密码管理器保存并填充包含四位编号的完整账号；关闭面板后棋盘不误投放、原暂停与每日资格不变。不得把这些项目改写为“全部移动端已通过”。

A07 可以准备发布清单与回退方案；上线仍需单独授权，并明确处理上述人工项和目标容量检查。Caddy 部署组合必须包含 `compose.proxied.yaml`，不得以单独 base Compose 抢占80/443。
