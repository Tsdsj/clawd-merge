## 方案选择

| 方案 | 收益与代价 |
| --- | --- |
| **本地图片 + 同题链接（推荐）** | 满足 T11 分享卡与好友挑战目标；无新增服务费用，离线可生成本局卡片，平台不支持时保存/复制降级 |
| 仅文字和链接 | 实现最小，但缺少可保存的成绩卡，不完整满足当前计划 |
| 托管成绩页/动态预览图 | 可提供统一外部预览和权威记录，但增加公开接口、存储及维护，留待真实传播需求验证后再考虑 |

推荐首版只做每日挑战，不增加实时房间、好友关系、短链、远程头像或自动社交发布。

## 信息与交互

1. 结果页增加“分享这一局”，保留再挑战和今日榜。分享不耗机会、不修改结果、不中断补传。
2. 分享预览突出分数，辅以昵称、最高 Clawd/等级、题目日期、投放次数、规则版本和完整同题链接。正式已提交、正式待提交、练习三种状态明确标注。不把本机图片当作成绩证明，不写会变化的排名。
3. 使用本地 Clawd 像素图代替远程头像，避免 CORS 或头像失败阻断导出。推荐 PNG 900 px 宽，按内容确定高度；昵称最多两行并省略，中文按真实字体测量，长链接允许换行。字体准备好后再绘制，失败用系统字体；导出图片和预览使用同一绘制结果。
4. 支持的设备由用户点击后调用系统分享；需检测文件分享能力。用户取消安静回到预览，不能提示发送成功。系统 API 完成只表示交接完成，不证明对方已收到。平台若不保留附带 URL，卡片内仍保留完整可阅读链接，并始终提供复制入口。
5. 无文件分享能力时提供保存 PNG 和复制链接。保存受限则打开本机图片预览并提示长按保存；剪贴板失败则给可选择的链接，手动复制。生成失败或生成中仍能复制链接。异步绘制失败可重试，旧回调不能覆盖后来打开的另一局。
6. 朋友打开链接先看到邀请，不自动开局、不自动换模式覆盖存档。今日正式按钮进入既有每日入口：使用接收者自己的身份、次数和开局确认。旧题只练习。新练习将替换挑战存档时先确认，正式机会不退；经典存档保留。无法安全持久化的旧正式结果仍沿用 T10 的保护。
7. 核验中和核验失败不开放正式开局，不把设备日期当服务器日期；可重试或回原游戏。日期非法、未来题或未知规则提供说明，不偷偷替换成今日题。旧题须使用明确支持的规则重建同一序列，不能迁移为另一版本。

## 链接与权威边界

建议格式（待实施）：

```text
https://tsdsj.github.io/clawd-merge/#challenge=2026-10-03&rules=daily-1&target=3465
```

- 只允许题目日期、受支持的规则版本和可选目标分；目标分为有界整数，仅作挑战目标。接收界面始终标记“分享者填写 · 未经核验”。链接不携带正式/练习认证标记，不据此写排行榜。
- 不携带 token、sessionId、requestId、playerId、昵称、OAuth 参数或 API override；分享使用明确的公开产品地址，不复制当前页面可能含有认证参数的完整 URL。
- 同日正式题由 T10 的服务端 today 返回确认；旧日练习根据已支持规则重建。无须为首版新增公开成绩证明接口或数据库表。
- 日期、长度、重复字段和版本需严格解析；不允许任意跳转地址或 HTML。OAuth 返回和新 hash 邀请要隔离处理，不能误解析登录回调或在未保存原局时跳走。
- “正式 · 已提交”只能来自本局已持久化服务端接受记录。待提交卡片不能因用户切换账号或领取新局而借用其他成绩的接受状态。已下载的待提交图片不会自动升级；再次打开预览才按当前本局状态重新生成。
- 图片上公开昵称由用户在预览中看见后主动分享；链接本身不包含身份。无远程图片托管、无第三方数据采集。
