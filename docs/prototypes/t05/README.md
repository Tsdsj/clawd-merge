# T05 经典模式断点续玩设计

日期：2026-10-02。状态：用户已确认，本地正式实现已接入；本目录保留为独立设计依据。

本轮可查看 `http://localhost:5174/docs/prototypes/t05/`。顶部选择器切换十种状态：本地恢复、在线恢复、正在核验、过期、换账号、核验失败、多标签页、交接无响应、损坏／不兼容、保存不可用。棋盘和数据是示例；不操作 localStorage，不访问排行榜，不影响正式游戏。已复用现有主题与像素素材。

## 产品规则

- 首版只保留当前浏览器、当前 API 环境的一份未完成经典对局，不做多档位、云存档或跨设备续玩。
- 没有存档仍按 T03 直接开玩；有存档先显示最近保存时间、分数、最高等级、投放次数、当前／下一只和钳子数量，等待玩家选择。
- 点“继续”恢复保存位置后才开始运行，不自动补投；不把关闭页面期间的时长算入狂热、死亡倒计时或冷却。
- 关闭恢复提示只暂不恢复，不删除旧档，也不能由空白棋盘自动覆盖它。可查看账号或帮助，再回到“继续上局”。新开一局须二次确认后才替换旧档。
- 完成的对局不再作为未完成存档恢复。结果上传后的可靠保存与补传属于 T06，不能借刷新重复提交或重开同一在线局。

## 对局恢复与上榜资格分开

| 状态 | 可选操作 | 对原存档的处理 |
| --- | --- | --- |
| 本地局有效 | 继续；新开 | 继续仍为本地局 |
| 同账号且原 session 可用 | 沿用原凭证继续 | 不申请新 session，不重置有效期 |
| 凭证过期或已失效 | 本地继续；新开 | 选择本地继续后持久化降级，不能之后补交 |
| 当前身份不同 | 暂不恢复并切回原身份；本地继续 | 不能把旧局成绩转交新账号 |
| 网络核验失败 | 重试；本地继续；稍后 | 未选择前保持旧档和资格不变，不擅自降级 |
| 另一页占用 | 请求接管；稍后 | 成功交接前本页只读 |
| 存档损坏或版本不兼容 | 保留旧档；确认新开 | 不循环报错，不自动删档 |
| 存储不可用或写入失败 | 临时游玩；重试 | 明确“未保存”，不谎报成功，不清空旧档 |

建议在 T05 增加最小的**只读恢复核验**能力：根据当前 token 校验存档 session 是否属于当前玩家、是否已消费、是否过期，返回服务端时间与到期时间。只读核验不消费或续签凭证、不创建新局、不实现 T06 补传；不要只凭客户端时钟就承诺仍可上榜。接口字段和错误码在实施时与现有 Worker 契约一起测试。核验成功也不绕过最终成绩提交时的服务端校验。

## 保存内容与时机

使用独立存档模块，快照包含 `schemaVersion`、`rulesVersion`、稳定 `roundId`、保存时间、模式和 API 环境。

- 每只刚体的等级、位置、线速度、角度、角速度与恢复稳定性所需睡眠状态；质量和碰撞体由对应规则版本重新生成，不能信任任意导入数据。
- 分数、最高等级、已投放次数、当前／下一只、瞄准位置、钳子、冷却、危险计时、连击时间、狂热和最高分提示状态。
- 在线局的 playerId、sessionId、签发／到期信息；不在存档中复制账号 token，不把机器凭据写入仓库。
- 不保留正在按住的按键、拖动或 pendingDrop。粒子、音效与一次性解锁卡不要求重放，也不能因恢复再次发放钳子或加分。

先完成内存快照，再原子替换一条存储记录；序列化与校验失败不得覆盖上一份成功快照。保存发生在投放、合成、道具操作之后，合并高频变化并节流；后台／失焦暂停前后补保存。不能依赖 unload，也不逐帧写磁盘。中途物理仍在运动时，快照必须能恢复连续状态，不能只保存静止位置。

恢复先校验有限数值、等级、数量与版本，再重建世界和接触缓存，验证不会穿模、爆炸或立即误判死亡。恢复失败回到可理解的提示，不反复自动加载坏数据。保存失败后保留当前内存对局，并显示非阻断状态；重试只在真的写入成功后显示“已保存”。

## 多标签页交接

优先采用浏览器提供的可靠互斥能力，让同一 API 环境的存档只有一个写入者；消息通道只用于通知，不作为唯一锁。具体兼容性在实施阶段验证。

1. 后打开的页面发现已有写入者，不能开始模拟、提交成绩或写入空白存档。
2. 点击“接管并继续”向当前页请求交接：当前页先暂停、落盘，再释放写入权。
3. 接管页真正获得写入权后读取最新快照；原页保持“已在另一页继续”，拒绝旧的延迟保存与提交。
4. 原页无响应时不靠几秒超时强行抢写；提示关闭原页后重试。页面关闭／崩溃后可恢复最后成功快照，不承诺最后一帧无损。
5. 浏览器缺少可靠互斥能力时，明确降级为临时游玩，不对现有存档进行不安全的并发写入。

接管后依然要核验原 session；两个标签页不得分别提交同一局。稳定 roundId 供 T06 幂等提交和待上传记录沿用，避免建立两套对局身份。

## 验收场景

刷新恢复棋盘、当前／下一只、分数、钳子和倒计时；恢复后不额外得分／奖励，不补投；移动中与刚合成时快照都能稳定恢复。覆盖未登录、同账号、换账号、凭证过期／已使用、核验断网、存档损坏、旧版本、存储拒绝、写入失败，以及双标签页同时打开／接管／原页无响应。

双页验收应核对实际写入和成绩请求，不能只看提示文案；不对线上真实玩家存档进行破坏性测试。

本轮已在浏览器检查桌面及 320px 竖屏，操作了新开确认／保留旧局、过期转本地、核验等待、接管成功演示及保存失败临时游玩。原型控制台未出现 warning/error。所有资格核验、交接与保存状态均为演示，不是正式功能验证。

## 已确认与实现

用户已确认恢复卡片与异常状态，以及三条边界：**本机单存档；主动选择转成本地局后不再上榜；跨标签页接管先交接，原页无响应不强抢。** 只读 session 恢复核验已纳入 T05，T06 继续负责可靠补传。

正式实现使用 `game-state.js`、`save-store.js`、`save-flow.js`。快照保存身份 ID 与 sessionId，不复制 token；恢复时由服务端返回到期状态，不把客户端保存时间作为上榜资格依据。互斥使用 [Web Locks 的 ifAvailable](https://developer.mozilla.org/en-US/docs/Web/API/LockManager/request)，不使用 steal；[BroadcastChannel](https://developer.mozilla.org/en-US/docs/Web/API/BroadcastChannel)只通知交接，获得锁才有写入权。修改物理或玩法兼容性时应更新 `RULES_VERSION`，不静默套用新规则到旧档。
