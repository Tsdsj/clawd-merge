# Clawd Merge 开发规划

日期：2026-10-02  
状态：M2 已发布，生产接口/桌面检查通过，真人设备项待补验；M3-01 原型/规范已完成，M3-02 尚未实施
代码基线：`903fea6`（编写时本地 HEAD）

## 1. 目标与开发边界

将现有合成小游戏逐步完善为适合随时开玩、能够保留成果、具有每日挑战与好友传播能力的轻量社区游戏。

本次授权为编写开发文档，不代表已经批准全部功能实施、修改线上数据库或发布上线。文中的产品规则是推荐方案，未决项集中列在第 10 节。任务编号用于后续引用，不引入新的工程管理框架。

基本原则：

- 保留像素 Clawd、现有合成手感、经典模式和历史成绩。
- 沿用原生 ES Module + Canvas、GitHub Pages、Cloudflare Worker + D1，不为新增功能迁移框架。
- 优先解决进场、暂停、存档和成绩可靠性，再增加竞争玩法。
- 新模式使用独立规则与榜单，不直接与经典模式历史分数比较。
- 外观奖励不改变碰撞体、掉落概率或得分能力。
- 新入口、模式选择、存档恢复、挑战和结算页面先做可查看原型，经设计确认后实现；明确缺陷修复沿用现有界面。

## 2. 当前基线与证据范围

### 已有能力

- 11 级 Clawd、复合圆刚体物理、合成升级与最高级消除奖励。
- 连击、狂热、彩虹万能牌、钳子、首次发现图鉴。
- 鼠标、触屏、键盘操作及音效、震动反馈。
- LINUX DO 登录、游客身份、游客成绩合并、多设备账号。
- 每人最佳成绩、前 20 名、加载更多、固定显示个人排名。
- GitHub Pages 前端与 Worker/D1 排行榜部署配置。

### 本轮已经检查

- 已阅读游戏规则、主循环、物理碰撞、排行榜客户端和服务端关键代码。
- 后台浏览器打开线上首页，确认首次访问显示登录／起名弹窗，默认没有直接离线开玩的入口。
- `npm test`：12 项后端测试通过。该结果是当前基线，不代表后续改动后的验证结果。
- 尚未重新验证真实 OAuth 完整流程、完整长局、手机触控、弱网及长期稳定性。
- 本地源码状态与线上完整版本一致性尚未逐文件核对；静态发现不等于线上复现。

### 当前关键问题

| 问题 | 依据 | 影响 |
| --- | --- | --- |
| 身份选择阻挡开玩 | `src/main.js` 的 `askName`、`initAccount`；线上首屏 | 新玩家需要先作账号决策 |
| 无当前对局存档 | `src/game.js` 仅保存 best、seen | 刷新或页面被回收后进度丢失 |
| 弹窗未暂停游戏 | `src/main.js` 的 `frame` 始终调用 update | 看榜期间仍可能消耗狂热时间或结束游戏 |
| 成绩缺少可靠重试 | `src/leaderboard.js` 的 `submit` 提前清除 session | 网络异常后玩家难以恢复上传 |
| 生产环境可覆盖 API | `src/leaderboard.js` 接受任意 `?api=` | 已有 token 可能被发送到非预期目标 |
| 最佳成绩存在并发覆盖风险 | Worker 先比较旧值，再无条件 UPDATE | 多设备同时提交可能使纪录回退，待隔离测试复现 |
| 核心玩法缺少自动回归 | 当前 test 脚本只执行排行榜测试 | 规则与物理调整缺少保护 |

## 3. 开发阶段与交付顺序

| 阶段 | 目标 | 主要任务 | 放行条件 |
| --- | --- | --- | --- |
| M1 基础可靠性 | 能直接玩，操作不误伤，成绩不轻易丢失 | T01—T07 | 关键缺陷回归通过，经典模式实际验收通过 |
| M2 每日挑战 | 每天有共同题目，结果便于比较和分享 | T08—T12 | 同题规则可复现，模式成绩隔离，分享流程通过 |

推荐顺序：先 T01、T02；同时准备 M1 原型；随后完成 T03—T07。M1 稳定后再确认 M2 详细设计。

## 4. M1：基础可靠性

### T01 收紧生产 API 目标

- **交付**：生产页面固定使用配置地址；本地调试仅允许明确的开发来源与目标，不将生产身份带入不可信 API。
- **涉及**：`src/leaderboard.js`、`src/config.js`、开发说明与客户端相关测试。
- **方案**：生产忽略或拒绝 `?api=`；本地开发按 API 环境隔离身份存储。保持现有线上身份可用，不进行无必要的 token 重置。
- **验收**：带任意 API 覆盖参数访问生产页面，不向该目标发送请求或凭据；localhost 调试仍可连接本地 API。使用隔离测试 token，不向外部站点发送真实凭据。
- **实施记录（2026-10-02）**：本地代码已完成，纳入 T01 提交；未推送或部署。生产忽略覆盖参数；仅 loopback 页面可覆盖到 loopback HTTP(S) origin；本地身份按 API 隔离且不迁移来源不明的旧身份，线上原身份键保留。
- **验证记录**：先用新增测试复现覆盖和身份混用，再修复；`npm test` 共 29 项通过（12 项后端、17 项客户端）。真实客户端通过本地 HTTP API 与内存 D1 完成注册、身份读取、开局凭证及退出。未执行线上真实 OAuth 或浏览器端完整验收，不代表线上已生效。

### T02 修复最佳成绩并发更新

- **交付**：同一账号多个设备提交后，最佳分数不会下降，最高分的等级、时间保持一致。
- **涉及**：`leaderboard/src/index.js`、`leaderboard/test/api.test.mjs`。
- **方案**：先用可控交错请求复现，再使用数据库条件更新保护 best 字段；响应读取最终权威结果。保留现有同分先到者优先规则。
- **验收**：高低成绩以不同顺序并发完成，最终均保留高分；相同成绩不覆盖原达成时间；合法逐局记录与局数准确。
- **风险**：本地 SQLite 模拟器不能完全代表线上 D1 调度，发布前需在隔离 D1 环境验证关键行为。
- **实施记录（2026-10-02）**：本地代码已完成，纳入 T02 提交；未推送或部署。最佳成绩使用 `WHERE best_score < ?` 条件更新，分数、等级、时间一起修改；同分保持原纪录。`improved` 来自本次 UPDATE 的实际修改行数，响应在写入后重新读取数据库中的最佳成绩再计算排名。无需数据库迁移，API 字段不变。
- **验证记录**：新增 4 项双设备、不同 token 的受控交错请求测试，覆盖高分先写、低分先写、同分竞争和未破纪录请求返回最新结果；修复前 3 项失败，修复后全部通过。检查最终分数、等级、时间、局数、逐局记录数和榜单；`npm test` 共 33 项通过。未对线上或隔离远程 D1 执行请求；本地测试不能代替远程发布前检查。
- **D1 依据**：[batch 事务与结果顺序](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)、[返回对象 meta.changes](https://developers.cloudflare.com/d1/worker-api/return-object/)。本次不调整 session 消费和补传语义，那部分仍属于 T06。

### T03 直接开玩与轻量引导

- **交付**：未登录玩家可以立即开始；登录、起名与上榜作为明确可选操作。首次操作提示投放、同级合成和危险线规则。
- **涉及**：`index.html`、`src/main.js`、`src/style.css`、`src/leaderboard.js`。
- **依赖**：首屏、引导和结算入口原型确认。
- **推荐规则**：首版未登录对局保存本地纪录；登录后下一局获得在线成绩资格，不追溯上传缺少服务端凭证的旧局。界面需提前说明，避免让玩家误以为登录即可补交。
- **验收**：首次访问无需填写信息即可投放；API 不可用仍能玩；登录入口容易找到；引导只出现必要次数；触屏与键盘路径均可操作。
- **设计记录（2026-10-02）**：独立[交互原型](prototypes/t03/index.html)及[设计说明](prototypes/t03/README.md)已获用户确认，覆盖首屏、投放后、本地结算、弱网、已有账号、身份选择。
- **实施记录（2026-10-02）**：本地已实现，纳入 T03 提交；未推送或部署。首屏直接开玩，帮助与身份弹窗可关闭；三步引导及首次道具提示按浏览器保存。中途注册保留当前局，凭证与开局身份绑定；下一局才参与排名。登录失效、连接失败均非阻断处理；旧局异步结果不覆盖新局。没有数据库迁移或后端接口变化。
- **验证记录**：`npm test` 44 项通过（含新增 8 项客户端资格／异步竞态测试、3 项引导测试）。实际浏览器验证首次投放、键盘投放、中途游客注册不重开、下局获得资格、帮助与 Escape、失效身份降级、本地模拟 OAuth 回跳及退出。实玩得到 2398 分并进入本地结算，注册后查看榜单仍无成绩，确认旧分未补传。停止本任务本地 API 后验证仍可投放，榜单报错可关闭。检查 320px、390px 竖屏及 844×390 横屏。
- **验证边界**：浏览器窄屏不等于手机真机；未重新验证真实 LINUX DO 或生产部署。暂停仍属 T04，存档仍属 T05，可靠补传与超时重试仍属 T06。测试 API 使用内存 D1 和模拟 OAuth，不写线上成绩。

### T04 暂停与重开保护

- **交付**：主动暂停，打开账号／排行榜自动暂停，切后台暂停，重开防误触。
- **涉及**：`src/main.js`、`src/game.js`、`index.html`、`src/style.css`。
- **方案**：集中管理暂停原因，避免关闭弹窗误解除手动暂停；暂停物理、死亡倒计时、狂热、冷却与待执行投放。失焦清除方向键和触控状态，恢复时重置时间累积。
- **推荐规则**：从后台返回需要点击继续；已有投放的对局重开需确认，空局直接重开。未来限时模式另行定义暂停规则。
- **验收**：危险倒计时中打开榜单，等待后返回不会损失游戏时间；恢复不会瞬间补跑或意外投放；快捷键 R 与按钮采用相同保护。
- **设计记录（2026-10-02）**：独立[交互原型](prototypes/t04/index.html)及[设计说明](prototypes/t04/README.md)已获用户确认，覆盖手动暂停、后台返回、弹窗嵌套和重开确认。
- **实施记录（2026-10-02）**：本地已接入，纳入 T04 提交；未推送或部署。暂停按钮／P 与继续层；后台、失焦、pagehide 和弹窗原因分别管理。游戏层冻结物理、计时、冷却及特效，清除拖动、方向键与待投放输入；恢复重置帧时间和物理累积。R／按钮统一重开确认，空局与结束局直接重开，取消不清棋盘，确认才申请新局凭证。没有存档或后端变更。
- **验证记录**：`npm test` 48 项通过，新增 4 项暂停测试覆盖原因组合、真实 Game 的物理／危险／狂热／冷却／视觉时钟冻结、暂停输入拒绝、恢复不补投、重开保留最高分与图鉴。实际浏览器验证手动暂停→榜单→关闭仍暂停、取消重开保留暂停、R 键打开确认、确认重开和空局直接重开，以及 320px 窄屏；暂停后两次浏览器截图逐字节一致。
- **验证边界**：后台原因组合已自动化验证；当前浏览器导航返回会重新加载，不能作为实际切后台恢复证据。真实标签页后台／系统失焦与手机真机切换仍需发布前验收。不把暂停宣称为跨刷新恢复，也不延长服务端凭证有效期。

### T05 经典模式断点续玩

- **交付**：自动保存当前对局，重载后显示“继续游戏／新开一局”；存档损坏不阻止重新开始。
- **涉及**：`src/game.js`、`src/physics.js`、`src/main.js`；建议新增独立存档模块。
- **依赖**：T04；恢复弹窗原型确认；与 T06 统一对局身份定义。
- **方案**：使用带 schemaVersion、rulesVersion 的快照，保存刚体位置、速度、角度、等级、当前／下一个、分数、投放次数、钳子、计时状态等必要数据。物理接触缓存可重建，但需验证恢复瞬间的稳定性。特效不必完整持久化。
- **保存时机**：投放、合成、道具操作后节流保存，切后台补保存；不依赖 unload，也不逐帧写 localStorage。允许恢复到最近成功快照，不承诺系统强杀前最后一帧无损。
- **在线资格**：绑定开局身份与服务端 session；身份变化或凭证过期后可继续本地对局，明确提示不上榜。当前服务端凭证有效期为 3 小时，不能无说明地承诺无限续玩上榜。
- **验收**：刷新恢复棋盘、下一只与关键状态；恢复后不额外得分或重复奖励；损坏、旧版本、存储不可用、账号切换和多标签页冲突有可理解的处理。
- **设计记录（2026-10-02）**：[恢复交互原型](prototypes/t05/index.html)及[设计说明](prototypes/t05/README.md)已获用户确认，包括本机单存档、明确转本地、协商交接和只读凭证核验。
- **实施记录（2026-10-02）**：本地已实现，纳入 T05 提交；未推送或部署。版本化快照保留刚体、接触缓存、当前／下一只、计分、道具和计时；先校验再替换世界，不重放奖励或输入。按 API 环境保存，每秒最多一次自动快照，后台／离页补保存。使用 Web Locks 独占写入和 BroadcastChannel 交接；原页保存成功才释放，失败或无响应不强抢。损坏、不兼容、存储失败保留原记录；不支持安全互斥时临时游玩。在线恢复只读核验原 session，明确转本地后持久化清除上榜凭证；不包含 T06 补传。
- **接口与部署**：新增 `GET /api/session/check?sessionId=...`，详情见[接口文档](../leaderboard/README.md)。只核验本人凭证、返回服务端到期状态，不消费或续签，无 D1 迁移；上线时先更新 Worker 再发布前端。
- **验证记录**：`npm test` 共 63 项通过。覆盖运动／静止／刚合成快照、不重复奖励、非法快照原子拒绝、存储失败、跨环境隔离、旧页不能覆盖新身份、只读凭证状态及单写入者交接。真实浏览器完成本地 29 分刷新恢复、在线 19 分恢复与双页交接；旧页停止写入／提交；断开测试 API 后选择转本地，再刷新仍为本地局。恢复局继续实玩至 9764 分结束，清档后刷新不再提示恢复；最终版本恢复卡片在 320px 下无横向溢出。
- **验证边界**：真实浏览器使用本地 API、内存 D1 和隔离测试身份；过期／已使用凭证、坏档、写入拒绝通过自动化模拟，未破坏用户存档。未验证手机系统强杀、跨设备云恢复或生产 D1 部署；不承诺系统强杀前最后一帧无损。

### T06 成绩上传可靠性

- **交付**：成绩显示待上传、成功、可重试失败或不可恢复失败；短时断网不会立即丢失提交机会。
- **涉及**：`src/leaderboard.js`、`src/main.js`、Worker、D1 新迁移、API 测试。
- **依赖**：T02；与 T05 共用对局标识与版本字段。
- **方案**：客户端保留按账号与对局绑定的待上传记录，成功后删除；设置请求超时与有上限的退避重试。服务端以对局作为幂等键，同一内容重复提交返回已保存结果，冲突内容拒绝；凭证消费、结果写入与最佳成绩更新采用适当事务边界。
- **约束**：现有 session 在写成绩前被消费，不能只增加前端重试。旧客户端兼容与数据库迁移需一起设计；切账号不得把旧记录上传到新账号。
- **验收**：请求未到服务端、响应丢失、重复点击、页面刷新后重试均只记录一次；4xx 规则拒绝不无限重试；新开一局后旧请求不能覆盖新局结算信息。

## 7. 架构与数据约束

- **模块拆分按功能发生**：输入／弹窗协调保留在主入口；存档、规则、随机数、分享可独立模块化。不因文件长度单独重构全部代码。

- **对局身份稳定**：每局明确所属账号、模式、规则版本和在线资格；重开、切账号、刷新、补传均不得串局。
- **数据迁移增量进行**：新增 migration，不修改已应用迁移来重写线上历史；字段变化考虑旧版已打开客户端。
- **安全边界在服务端**：次数、模式资格、session 所属、重复成绩及权威排名由服务端校验。
- **维护成本**：继续复用现有服务，无新增付费 API 的必要；存储、查询、分享流量增长仍需观察现有配额。自定义域名仅在实际网络访问问题需要时另行决定。

## 8. 通用验收与发布

每个阶段交付：实际变更清单、对应测试结果、浏览器验证记录、已知限制、部署步骤与回退方案。实现、验证、部署、线上验收分别记录，不互相替代。

必要场景：

1. 桌面鼠标／键盘、手机触控、窄窗口与横竖屏。
2. 新游客、已有游客、LINUX DO 账号、登录失效与账号切换。
3. 无网络、慢请求、服务端失败、请求成功但响应丢失。
4. 刷新、切后台、打开弹窗、存档损坏、双标签页。
5. 经典计分保持兼容，新模式不会污染旧榜。
6. 每日边界、凭证过期、重复提交与并发提交。

发布前核对目标分支、Pages 发布来源和 Worker 环境；数据库变更先验证并确认可恢复方式。先部署兼容旧客户端的后端，再发布依赖新字段的前端；不兼容变化采用显式版本控制。回退前端时必须确认其仍可访问当前后端与数据库。

真实 OAuth、生产数据迁移与上线执行在获得对应授权后开展，不通过真实玩家数据制造测试成绩。

## 9. 首轮推荐交付包

建议先确认 **M1：T01—T07**，完成一个可独立发布的稳定性版本。

- 工程先处理 API 目标、最佳成绩并发与上传可靠性。
- 产品原型覆盖直接开玩、暂停／继续、重开确认、存档恢复和上传状态。
- 经典模式通过实际验收后，再进入每日挑战设计。
- 不把 M2、M3 的全部内容作为首轮上线的前置条件。
